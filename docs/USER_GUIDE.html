Complete guide to AlgebraKing. All the examples below were run on the algebraking binary (version 0.0.1) and the output shown is the real output, in 1-D format (the format used by scripts, by -e when the output is not a terminal, and by interface(prettyprint=0); see “Getting started”).

1 What it is

AlgebraKing is a computer algebra system for the terminal, inspired by the Maple language. It was written from scratch, in clean room: no Maple code, library (.mla), help text or data was used; the language comes only from public documentation and general knowledge of it. It reproduced 257/257 verdicts of a real verification suite originally run in Maple 18.

The architecture has two halves:

  • Rust handles the language: lexer, parser, evaluation (variables, procedures, loops, %, packages, with), 1-D and 2-D printing and the MCP server.
  • Python + SymPy handles the mathematics: every math function (int, solve, dsolve, Eigenvalues, …) is a call to an engine (engine/engine.py) embedded in the binary, which translates the AlgebraKing functions to SymPy and returns the result in the AlgebraKing convention.

Why does it exist? The main use is checking calculations: Claude takes a step of your derivation (derivative, integral, ODE solution, identity) and asks AlgebraKing, via MCP, whether it is correct, receiving equal, not_equal (with a counterexample) or undetermined. The second use is a terminal REPL. When the program does not know how to do something, it returns the expression unevaluated or raises an error; the rule is never to return a wrong answer with confidence.

Out of scope: GUI, worksheets (.mw), plot window (plot) and code generation, or byte-for-byte identical formatting to any other system.

2 Installation

2.1 Requirements

Item Version Note
Linux (tested on Ubuntu) any recent
Python 3 ≥ 3.8 the engine runs on it
sympy and mpmath SymPy 1.14 (tested) pip install --user sympy mpmath
Rust / cargo recent stable install.sh installs it via rustup if missing
claude (Claude Code) optional only to register the MCP server

2.2 Automatic installation

git clone https://github.com/phfmatias/AlgebraKing.git
cd AlgebraKing
./install.sh

The script is idempotent (it can be run again without problems) and does, in this order:

  1. checks for python3 >= 3.8 and import sympy, mpmath; if missing, runs python3 -m pip install --user sympy mpmath (if pip refuses with “externally managed environment”, it retries with --break-system-packages, only in the user directory);
  2. checks for cargo; if missing, installs rustup (minimal profile, no prompts) in ~/.cargo;
  3. cargo build --release;
  4. creates the symbolic link ~/.local/bin/algebraking pointing to target/release/algebraking (warns, with the exact line for ~/.bashrc, if ~/.local/bin is not in PATH);
  5. runs a self-test: algebraking -e 'int(x^2,x);' must print x^3/3;
  6. registers the MCP server in Claude Code, if the claude command exists (and skips if claude mcp get algebraking already answers);
  7. prints a summary with the next steps.
Flag Effect
--no-mcp does not register the MCP server in Claude Code
--no-python-deps does not check or install sympy/mpmath
--prefix DIR symbolic link directory (default: ~/.local/bin)
-h, --help help

2.3 Manual installation

python3 -m pip install --user sympy mpmath
cargo build --release
mkdir -p ~/.local/bin
ln -sfn "$PWD/target/release/algebraking" ~/.local/bin/algebraking
export PATH="$HOME/.local/bin:$PATH"          # coloque no ~/.bashrc
algebraking -e 'int(x^2,x);'                   # x^3/3

2.4 Updating

git pull && ./install.sh

2.5 Uninstalling

./uninstall.sh

Removes the symbolic link, the MCP registration (claude mcp remove algebraking -s user) and the engine cache (~/.cache/algebraking). It never deletes the repository folder; delete it by hand if you want. The REPL history (~/.algebraking_history) is also kept.

3 Getting started

3.1 The four ways to use it

algebraking                  sessão interativa (REPL)
algebraking arquivo.mpl      executa um script
algebraking -e "código"      avalia uma string
algebraking mcp              servidor MCP no stdin/stdout

Also: algebraking -V (version) and algebraking -h (help).

3.2 The REPL

The prompt is >. A statement can span several lines: while it is incomplete, the prompt becomes . Ctrl-C discards the pending input, Ctrl-D (or quit;) exits. The history (arrow keys, Ctrl-R) is saved in ~/.algebraking_history.

3.3 ; shows, : silences

; shows the result and : suppresses it (the last statement may omit the terminator):

> a := 5; b := a^2: c := a + b;
a := 5
c := 30

(Real output of algebraking -e 'a := 5; b := a^2: c := a + b;'.)

3.4 %, %%, %%%

% is the last result shown, %% the one before it, %%% the one before that:

x^2 + y; %; %%;

x^2+y
x^2+y

3.5 2-D or 1-D

In the REPL, and in scripts/-e when the output is a terminal, results are printed in 2-D (as above). When the output goes to a pipe or file, they are printed in 1-D. To force it: interface(prettyprint=0) (1-D) or interface(prettyprint=1) (2-D).

3.6 .mpl scripts

A script is a text file with AlgebraKing statements. The program prints the results of the statements ending in ; and stops at the first error, with exit code 1.

$ cat stop.mpl
a := 2;
b := a^10;
error "parou aqui";
c := 3;
$ algebraking stop.mpl; echo "rc=$?"
a := 2
b := 1024
Error, parou aqui
rc=1

3.7 Exit code

Code Meaning
0 all good (or quit called in the script)
1 evaluation or syntax error in script/-e; unreadable file; engine fails to start
2 incorrect command-line usage (unknown option)

4.7 Packages: with, :- and []

There are three ways to call a package function, and the short name only works after with:

LinearAlgebra:-Determinant(<<1|2>,<3|4>>);
-2

LinearAlgebra[Transpose](<<1|2>,<3|4>>);
Matrix(2, 2, [[1, 3], [2, 4]])

with(LinearAlgebra): Determinant(<<1|2>,<3|4>>);
-2

Determinant(<<1|2>,<3|4>>);
Determinant(Matrix(2, 2, [[1, 2], [3, 4]]))

(The last one does not resolve the short name and returns the call unevaluated.) Recognized packages: LinearAlgebra, inttrans, VectorCalculus, student, numtheory, Groebner, combinat, ListTools, DEtools. When two packages export the same name (for example Basis, in LinearAlgebra and Groebner), the last one loaded with with wins.

6 Using with Claude (MCP)

MCP (Model Context Protocol) is the protocol through which an assistant such as Claude calls external tools. algebraking mcp is an MCP server that talks over stdin/stdout (JSON-RPC 2.0): Claude sends the step of your calculation and receives the verdict.

6.1 Automatic registration

./install.sh already does the registration (if the claude command exists). To redo it:

./install.sh

6.2 Manual registration

claude mcp add algebraking -s user -- "$(command -v algebraking)" mcp

(the -s user scope applies to all your projects). To verify:

claude mcp list              # algebraking deve aparecer como conectado
claude mcp get algebraking   # mostra comando, argumentos e estado

Inside Claude Code, the /mcp command shows the servers and tools. Sessions that are already open must be restarted to load a newly registered server.

6.3 Claude Desktop

Edit ~/.config/Claude/claude_desktop_config.json (Linux) and use the absolute path of the binary (JSON does not expand ~):

{
  "mcpServers": {
    "algebraking": {
      "command": "/home/SEU_USUARIO/.local/bin/algebraking",
      "args": ["mcp"]
    }
  }
}

Restart Claude Desktop after saving.

6.4 The 8 tools

All of them accept AlgebraKing syntax. Arguments with ? are optional. session? selects a named session (default "main"). All the checking tools accept field?: real (default, because physics and chemistry calculations use real variables) or complex.

Tool Arguments What it does
algebra_eval code, session? runs AlgebraKing statements in a persistent session and returns each result in 1-D, plus the LaTeX of the last one
verify_equal lhs, rhs, assumptions?, field?, session? decides whether lhs = rhs on the common domain: verdict, method, conditions, domain of each side, difference, counterexample inside the domain, hypothesis suggestion and limitations
check_derivative f, derivative, var (+ assumptions?, field?, session?) checks whether diff(f, var) is the stated derivative
check_integral integrand, antiderivative, var (+ assumptions?, field?, session?) checks whether diff(antiderivative, var) is the integrand (correct antiderivative up to a constant)
check_solution equations, solution (+ assumptions?, field?, session?) checks each candidate in the original equation and its domain, lists the rejected ones and says whether the accepted ones are all the solutions
check_step before, after, var? (+ assumptions?, field?, session?) classifies a solution step: equivalent, implies (spurious solutions), is implied (lost solutions), not equivalent or undetermined
check_ode_solution ode, solution, func (+ assumptions?, field?, session?) like odetest: substitutes into the ODE and the initial conditions
algebra_reset session? restart of the session

assumptions is a string such as "x>0, n::integer". In check_solution, equations can be an equation or a set ({x+y=3, x-y=1}); an expression e means e = 0; solution is one candidate (x=2, {x=2, y=1}) or several ([x=0, x=3], [{x=1, y=2}, {x=2, y=1}]). In check_ode_solution, the ODE can come in a set with initial conditions.

6.4.1 Response fields

The first line is always verdict: equal | not_equal | undetermined, but the verdict alone is not enough. Also read:

Field Meaning
method symbolic (proof), numeric (sampling), convergence, solveset, domain
field field used: real or complex
conditions existence conditions of the common domain, in AlgebraKing syntax (x <> 1, abs(x) < 1, sin(x) <> 0). equal holds only where they hold
domain domain of each side, the common one, and whether both sides have the same natural domain (same domain: no, they differ where x = 1)
counterexample only appears with a point inside the common domain, with the values of each side
outside the common real domain point where one side is real and in its domain, and the other is not real (for example 2*ln(x) with x < 0)
suggestion hypothesis under which the equality was proved symbolically (equal if x >= 0); does not change the verdict
note / limitation explanations and what was not proved (sampling, convergence, sets that solveset did not solve)
assumptions used the session hypotheses and those from the assumptions argument

sum, product and int reach the engine inert (Sum, Product, Int) in the checking tools, so that the convergence condition is not lost; in algebra_eval and the REPL they keep returning the closed form.

6.5 How the verdict works

verify_equal (and the tools check_derivative, check_integral, check_ode_solution and check_step with two expressions, which use it underneath) follows this procedure, over the requested field (real by default):

  1. For lists, sets, equations and matrices, it compares element by element (no domain analysis; the report warns about it).
  2. Sum, Product and Int are computed keeping the SymPy condition (abs(x) < 1); convergence at the boundary and at two points outside is tested and reported. A divergent series has no value; a series whose convergence cannot be decided never gives equal.
  3. It collects the existence conditions of each side: denominators <> 0, argument of ln (> 0 over the reals, <> 0 over the complexes), roots and fractional powers (>= 0 over the reals), poles of tan, cot, sec, csc, ranges of arcsin, arccos, arctanh, etc. Conditions already guaranteed by the hypotheses disappear. The excluded sets come from solveset; when it cannot solve, the condition stays symbolic and a limitation warns about it.
  4. It tries to prove lhs - rhs = 0 symbolically on the common domain (simple conditions, such as x > 0, become hypotheses). Zero → equal, method symbolic.
  5. Numerical test: random points at 40 digits, only where both sides exist (and are real, in the real field) and satisfy the conditions. A clearly different point → not_equal with that point as the counterexample. A point where one side is real and the other is not → not_equal explained (outside the common real domain). All equal → numeric equal.
  6. equal means equal on the common domain; if the domains differ (x = 1 excluded only on the left, for example), the report says where.
  7. If the verdict is not equal and there are at most 2 variables, it tries a fixed menu of hypotheses (x >= 0, x > 0, x < 0, x::integer) and, if any gives a symbolic proof, shows suggestion. The main verdict does not change.
  8. Otherwise, undetermined. The program never raises an error for a mathematical reason.

What is proof and what is heuristic. Proof: equal with method symbolic, under the listed conditions and the declared hypotheses; the suggestion is also a symbolic proof under the suggested hypothesis, but the choice of hypothesis is heuristic (a fixed menu, not a complete search). Heuristic: numeric equal (sample points), divergence outside the condition of a series (tested at points), the domain comparison with two or more variables, and the classification of check_step when there are parameters (solveset treats them as generic). The check_step and the completeness of check_solution depend on solveset: when it returns ConditionSet, the answer is undetermined / not established, never a guess. Finally, the language automatically simplifies x/x to 1 and sqrt(x)^2 to x; the tool recovers these conditions by reading the input before evaluation, but not when the expression comes from a variable already assigned in the session.

Numeric equal is strong evidence, not proof. Real example: erf(x)+erfc(x) = 1 gives equal by method numeric, and that is correct. But sin(x)*Heaviside(x) against abs(sin(x))*Heaviside(x) also gives numeric equal, because the test points lie in [-3, 3] and the difference only shows up for x > π (at x = 4 the two expressions are sin(4) and -sin(4)). Be wary of identities with piecewise-defined functions, branches or behavior in distant regions. symbolic + equal is the only answer that counts as a demonstration.

The language’s verify(a, b) function (REPL and scripts) still returns only true, false or FAIL, using the old algorithm (no field or domain).

6.6 Sessions

Each server process keeps named sessions, each with its own interpreter: variables, Digits, assumptions and loaded packages persist between calls in the same session. Without session, "main" is used. Two sessions do not see each other:

algebra_eval  code="g := 3;"  session="s2"   ->  g := 3
algebra_eval  code="g + 1;"   session="s2"   ->  4

algebra_reset clears a session. Closing Claude Code ends the server and discards the sessions.

Variable Effect
ALGEBRAKING_TIMEOUT seconds per engine call (default 60). On timeout: the engine is killed, restarted and the error is Error, (in name) computation timed out after N s; the session’s variables and assumptions are kept
ALGEBRAKING_PYTHON engine Python executable (default python3); useful if SymPy is in another Python/venv

7 Known limitations

An honest list of what to expect. The goal is a correct answer first; output formatting is secondary.

Topic Behavior
solve returns all the solutions it finds, including those from several branches: solve(sin(x)=0, x) → Pi, 0
Order of solutions solve(x^2-5*x+6=0, x) → 3, 2
Order of terms and factors comes from SymPy’s internal form: (x-3)*(x-2)*(x-1), -sqrt(5)/2+5/2
Floating-point format 0.1362; 1.5*10^20
Names with assumptions assume(x>0) does not mark the name: x appears as x
Heaviside(0) 1/2
Last digits 15-digit floating-point results (numeric matrices, HFloat) may differ in the last two digits from other systems

Functions and packages that do not exist (the call comes back unevaluated or gives a syntax error): inttrans:-hilbert, LegendreQ, the Student package (Student[Calculus1]), isolate (comes back unevaluated), DEtools graphics. There is also no: graphics (plot, plots), graphical interface, .mw worksheets, code generation and the Statistics/StringTools libraries (the package name is recognized, but without functions).

The 1-D output is not byte-for-byte identical to any other system’s.

8 Troubleshooting

sympy/mpmath not found. Typical symptom:

Error, (in int) the math engine stopped:   File ".../engine-....py", line 29, in <module> |     import mpmath | ModuleNotFoundError: No module named 'mpmath'

Install: python3 -m pip install --user sympy mpmath (or run ./install.sh). If SymPy is in a Python different from the python3 in PATH, point to it with ALGEBRAKING_PYTHON=/path/python3. Do not pass -I or -s to Python: SymPy lives in the user’s site-packages.

Engine does not start. Wrong ALGEBRAKING_PYTHON:

Error, cannot start the math engine (/nao/existe): No such file or directory (os error 2)

cargo: command not found. Run ./install.sh (it installs rustup) or load the environment with source ~/.cargo/env and check cargo --version.

algebraking: command not found. ~/.local/bin is not in PATH. Add it to ~/.bashrc and open a new terminal:

export PATH="$HOME/.local/bin:$PATH"

MCP server shows as failed / does not connect.

  1. claude mcp get algebraking: check the registered command (absolute path of the binary

    • mcp) and that the file exists (ls -l on the path; the link breaks if the repository moved somewhere else).

  2. Test the server by hand (it should answer with one JSON line containing serverInfo):

    printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"t","version":"0"}}}' | algebraking mcp

  3. Redo the registration: claude mcp remove algebraking -s user and then ./install.sh.

  4. Restart the Claude Code session.

Timeouts. Error, (in series) computation timed out after 2 s: the engine was restarted and the session continues. Increase it with ALGEBRAKING_TIMEOUT=300; if it is a heavy symbolic calculation, consider simplifying it by hand or splitting it.

Cache without permission. Error, cannot create .../.cache/algebraking: Permission denied: the engine is written to $XDG_CACHE_HOME/algebraking (or ~/.cache/algebraking). Set XDG_CACHE_HOME to a writable directory.

Debugging. ALGEBRAKING_DEBUG=1 algebraking -e '...' shows the engine’s stderr ([engine] ...) and the Python tracebacks of internal errors. To test the engine in isolation:

echo '{"id":1,"op":"ping"}' | python3 engine/engine.py

pip error “externally managed environment”. install.sh already retries with --break-system-packages (only in the user directory). If you prefer, use a venv and point ALGEBRAKING_PYTHON to its Python, or sudo apt install python3-sympy python3-mpmath.
